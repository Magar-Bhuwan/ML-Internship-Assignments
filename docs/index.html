Abstract

Content teams often have more pages to review than they can manually evaluate, creating a need for a repeatable way to prioritize content-review effort.

This project uses 30,000 anonymized FlyRank content records to investigate whether historical content visibility, engagement, freshness, and related performance signals can help identify content associated with declining performance.

A Random Forest classifier is compared with a transparent freshness-and-visibility baseline using a grouped-by-client validation design intended to reduce client-level overlap between training and testing data.

On the shared test split, the Random Forest achieved 0.6798 precision, 0.7989 recall, and 0.7345 F1, compared with 0.6389 precision, 0.0130 recall, and 0.0255 F1 for the baseline.

The result supports using historical signals as directional decision-support evidence for prioritizing a human review queue, while the observational design and lack of a controlled refresh experiment mean the model should not be interpreted as proof that refreshing content will improve future search performance.

1. Introduction / Problem Statement

Content teams rarely have unlimited time to review every page in a large content portfolio.

Pages can differ in freshness, historical visibility, engagement, search demand, and performance direction. Treating every page as equally important can therefore make content-review work difficult to prioritize.

Research question:

Can historical content-performance signals and content freshness be used to prioritize which content should be reviewed first?

This capstone follows the Refresh / Content Opportunity Scoring lane.

The objective is not to automatically rewrite, delete, or publish content. The objective is to provide a repeatable evidence-based prioritization workflow that helps a human reviewer decide where attention should go first.

3.1 Baseline

The baseline uses two simple and interpretable signals:

  • days_since_last_update >= 104
  • impressions_90d >= 3,616

The baseline represents a practical rule: content that is both sufficiently stale and historically visible should receive higher review priority. 

score =
stale
× visible
× impressions_90d

3.2 Target and machine-learning model

The supervised learning task predicts whether a record belongs to the declining-performance class. 

declining_target =
(trend_direction == "down").astype(int)

A Random Forest classifier was trained using historical content, search-performance, visibility, engagement, and freshness signals.

3.3 Validation design

The model and baseline are evaluated using the same grouped-by-client test split.

Grouping by client is intended to reduce the risk that records from the same client appear in both training and testing data. This makes the evaluation more conservative than a simple row-level random split when multiple records may share client-specific patterns.

3.4 Leakage checks

Target-derived trend information is excluded from the predictive feature set.

  • trend_direction is not used as a model predictor.
  • trend_pct is excluded where it represents target information.
  • The baseline uses observable freshness and visibility signals.
  • The final evaluation compares both approaches on the same held-out client groups.

3.5 Decision-support design

The machine-learning model provides predictive evidence, while the transparent baseline converts freshness and visibility into an operational action queue.

Model → evidence. Baseline → prioritization. Human review → decision.

What the result means

The Random Forest achieved substantially higher recall and F1 than the simple baseline on this held-out evaluation.

The largest difference is recall. The baseline identifies very few of the declining cases, while the Random Forest captures a much larger proportion of them on the test split.

Important interpretation boundary

Better classification performance does not prove that acting on the recommendations will improve future search performance. The result demonstrates predictive performance on the available evaluation data, not causal impact.

5. Ranked Recommendations / Action Playbook

The analytical output is converted into a practical review queue. The recommendations are intentionally designed for human decision-making rather than automatic content changes.

Priority 1 — Review stale and visible content
stale_and_visible

days_since_last_update >= 104 AND impressions_90d >= 3,616

Action: Review first for freshness, accuracy, completeness, search-intent alignment, and potential content improvements.

Priority 2 — Monitor stale content
stale

Content is sufficiently old but does not meet the visibility threshold.

Action: Monitor and consider review when additional evidence indicates declining performance or strategic importance.

Priority 3 — Monitor visible content
visible

Content has meaningful historical visibility but does not meet the freshness threshold.

Action: Continue monitoring rather than automatically refreshing.

Priority 4 — No strong baseline signal
no_strong_signal

The content is neither sufficiently stale nor sufficiently visible according to the baseline thresholds.

Action: Do not prioritize immediate review based on this baseline alone.

Top-20 review queue

The underlying capstone analysis produces a ranked Top-20 review queue. The highest-priority candidates are content items matching the stale-and-visible condition.

The Top-20 list is a review queue, not an automatic refresh list.

A human reviewer should determine whether a page is actually outdated, incomplete, inaccurate, or strategically important before making any content change.

6. Limitations & Honest Framing

Observational data

The analysis is based on historical observational data. It does not establish that any particular signal causes a decline in search performance.

No controlled refresh experiment

This project does not test the causal question: "If this content is refreshed, will its future performance improve?"

Answering that question would require a properly designed intervention and future outcome measurement.

Dataset-specific thresholds

The 104-day freshness threshold and 3,616-impression visibility threshold are derived from the project analysis. They should not automatically be treated as universal thresholds for every website or future dataset.

Model errors

The Random Forest can produce false positives and false negatives. A prediction should therefore be treated as a prioritization signal, not as an automatic decision.

No claim about Google's algorithm

This project does not reverse-engineer or prove Google's ranking algorithm.

The analysis studies observable historical signals in the available FlyRank dataset. It should not be interpreted as evidence of how Google's ranking system works internally.

Appropriate language

The findings should be described using terms such as:

  • observed
  • measured
  • associated with
  • directional
  • decision-support
  • review candidate

Conclusion

Historical content-performance signals can provide useful evidence for prioritizing content-review effort.

In this evaluation, the Random Forest produced substantially stronger recall and F1 than the simple freshness-and-visibility baseline on the grouped-client test split.

The practical recommendation is to use the model and transparent action rules as decision-support tools, followed by human review, rather than automatically changing content.

Next validation step:

A future version should evaluate recommendations against a properly separated future-performance window or a controlled refresh experiment to test whether recommended actions actually improve outcomes.
